{{ ui.icon('link') }} Connect Jira

Cloud, Server or Data Center

Add this to Settings, and set the token as an environment variable on this computer (an API token for Jira Cloud, a personal access token for Server).

trackers:
  jira:
    enabled: true
    base_url: https://yourorg.atlassian.net
    project_key: UR
    email: qa.lead@example.com
    token_env: AGENTQA_JIRA_TOKEN

{{ ui.icon('link') }} Connect Azure DevOps

Services or Server

A personal access token with Work Items (Read and write) is enough.

trackers:
  azure_devops:
    enabled: true
    org_url: https://dev.azure.com/yourorg
    project: Example Portal
    token_env: AGENTQA_ADO_TOKEN

To try it without a tracker, run python -m agentqa demo-trackers and point base_url at http://127.0.0.1:8900/jira.

{{ 'after every Triage' if tcfg.sync and tcfg.sync.auto else 'when you press Sync now, or with agentqa sync' }}
1. Confirma QA lead confirms the defect
2. SendAgentQA opens the issue with evidence
3. Fixthe developer marks it fixed
4. Re-testthe next run checks it again
5. Close or reopenverified fixed, or reopened with the new failure

An issue closed as Won't Fix, Duplicate or Rejected rejects the AgentQA defect, and later runs leave it rejected.
